# 唐人街探案馆公开产品研究

研究日期：2026-08-31  
目标站点：[tanghenre.com](https://tanghenre.com/)  
用途：为 FunnyGames 的原创子游戏“盲汤”提炼可复用的产品机制，不复制题面、汤底、美术、音频或社区内容。

## 调研范围与边界

- 读取公开首页、关于页、官方题目、用户实验室、创作页、社区页、登录/注册界面、站点地图和公开 GitHub 项目。
- 完成一局无需登录的公开题目试玩，验证 AI 判定、轮次限制和自动通关流程。
- `robots.txt` 允许公开页面，但禁止 `/api/`、`/_next/`、`/admin/`，并要求 1 秒抓取间隔；调研遵守了这些约束。
- 未读取 Cookie、本地存储、密码、后台接口或管理员路径，未绕过认证，也未批量保存用户题库内容。
- 注册需要用户提供邮箱和密码，因此只检查了表单与校验规则，没有代建账号。

## 站点规模

公开站点地图共计 437 个 URL：

| 类型 | 数量 | 观察 |
| --- | ---: | --- |
| 用户创作题目 | 392 | 构成内容长尾，带作者与互动数据 |
| 官方题目 | 42 | 由站方筛选，带独立插画和环境音 |
| 其他产品页面 | 3 | 首页、实验室/创作等入口 |

这个规模说明产品的核心壁垒不是“即时让 AI 写一题”，而是经过筛选的内容库、真实玩家问答数据，以及持续互动形成的质量排序。

## 核心玩法实测

匿名用户可以直接开始推理。题面固定展示，AI 主持人把玩家的问题判为“对 / 错 / 不相关”，问题与回复按时间顺序保留。默认最多提问 8 次，AI 会在轮次耗尽前识别玩家是否已经触及核心答案。

完成公开题目“数数”时，测试流程为：

1. “他在数数字吗？”得到“对”。
2. “我能看见他吗？”得到“对”。
3. “他知道我的存在吗？”触发“猜对了”。

结算层会揭示汤底，并提供三类情绪反馈、评论和“下一题”入口。这形成了很短但完整的闭环：读题、有限追问、自动识别、即时反馈、继续下一题。

## 功能清单

### 首页与发现

- 官方精选与用户创作分区。
- 题目卡片公开互动量和好评率，降低选择成本。
- 用户实验室支持搜索、按好评或最新排序。
- 内容区分原创与转载，显示作者、浏览、试玩、评分和时间。
- 作者资料页把单题消费延伸为关注创作者。

### 创作与分发

- 创作者填写标题、汤面和汤底，并声明原创或转载。
- 可配置 3–20 次提问上限。
- 支持保存草稿和提交审核。
- 用户题目在获得至少 20 次反馈且好评率达到 30% 后，才有资格进入首页推荐。

这套门槛同时解决冷启动和低质量内容污染：新内容先在实验室获得真实反馈，达到最低样本量后才参与首页分发。

### 账号与社区

- 登录采用站内邮箱/密码表单。
- 注册要求 2–15 字昵称、邮箱和至少 8 位密码。
- 登录后可同步进度、记录完成题目、评论和参与社区。
- 社区有闲聊/反馈分类，以及点赞、评论、浏览等基础互动。

### 体验与工程

- 每道官方题有独立插画和环境音，强化题目的记忆点。
- 站点提供 PWA manifest，采用竖屏、standalone 运行模式。
- 页面包含 Google Analytics 与 AdSense。

## 关于页透露的产品策略

创作者表示曾审阅约 1,500 个故事，最终只保留 80 多个逻辑较完整的题目。早期尝试让 AI 直接生成题目，但成品质量不稳定，因此调整为“人类策展内容，AI 只做裁判”。

这是对盲汤最重要的启示：生成模型适合帮助创作者扩写、检查结构和生成变体，但正式题库需要人工筛选；推理过程中则使用成本更低、输出更稳定的判定模型。

## TurtleBench

站点把 4,448 条真实玩家提问整理成 TurtleBench，覆盖 11 个模型。公开仓库为 [mazzzystar/TurtleBench](https://github.com/mazzzystar/TurtleBench)，Apache-2.0 许可，调研时约 161 stars。

它用客观的 yes/no/unknown 标签评估模型，并持续吸收真实玩家的新问题，减少模型针对固定题集刷分的空间。对盲汤的直接价值是：模型智测不应只比较“最后猜没猜中”，还应比较有效问题率、关键事实覆盖率和轮次效率。

## 可借鉴与不可复制

可以借鉴的是通用产品机制：有限轮次、三分类裁判、自动结算、精选与社区题库分层、质量门槛、连续下一题、客观模型评测。不能复制的是具体题面与汤底、插画、音频、品牌视觉、社区文本和非公开数据。

盲汤采用以下原创映射：

| 市场验证过的机制 | 盲汤的原创实现 |
| --- | --- |
| 精选题目优于纯 AI 随机生成 | “汤局档案”放人工编写原创题；“创作桌”保留 AI 即兴模式 |
| 默认 8 次追问 | 人类局固定 8 轮，顶部和输入区持续显示剩余次数 |
| AI 自动识别成功 | 根据已覆盖的关键事实累计计算还原度，达到阈值自动通关 |
| 三类结算反馈 | 使用“合理 / 意外 / 神来一笔”本地反馈，不复用原站文案与数据 |
| 下一题闭环 | 从当前精选题顺序进入下一碗原创汤 |
| 搜索和排序 | 支持标题、标签、作者搜索，以及好评/最新排序 |
| 客观模型基准 | 继续使用真相覆盖率、有效问题率和轮次效率评估多个模型系列 |

## 目标站的优势与空档

优势在于内容策展、真实提问数据、非常短的局内反馈回路，以及题目插画/环境音带来的氛围。弱点是创作仍然以表单为主，用户无法直观看见故事元素之间的因果结构；同时“模型生成质量不稳定”被当作限制，而不是创作辅助能力。

盲汤应把差异化放在可移动的关系画布：玩家拖入物件、人物、地点、时间和异常，并用连线表达潜在因果。AI 负责把结构扩写成候选汤底，人类再将优质版本收录进精选档案。这样形成“可视化创作 -> 人工策展 -> AI 裁判 -> 模型智测”的完整链路。

## 后续优先级

1. 接入服务端裁判网关，让每轮只返回结构化的 verdict、matchedFacts 和 solved。
2. 把本地进度、结算反馈和最近游玩写入浏览器持久存储。
3. 增加创作者草稿、人工审核和最低反馈样本门槛。
4. 为精选题制作原创插画与可关闭的环境音。
5. 从真实匿名问答中建立脱敏评测集，持续校准 DeepSeek、Claude、Codex 与开源模型。
